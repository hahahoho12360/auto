# Project 1. 자동화 도구 비교 구현

Make vs Zapier 비교 분석

보고서 목적 동일한 자동화 업무를 Make와 Zapier에 각각 구현한 결과물을 과제 요구사항에
맞춰 정리하고, 실제 실행 증빙·비교 항목·요금/보안 리스크를 점검한 보고서입니다.

작성 기준일  2026. 8. 16.

## 1. 과제 개요 및 최종 판단

### 1.1 과제 목표

서로 다른 2개 이상의 노코드 자동화 도구를 직접 사용하여 동일한 워크플로우를 구현하고,
Trigger·Action·조건 분기·실행 결과를 실제로 확인한 뒤 도구별 특성을 비교 분석하는
과제이다.

| 평가 항목 | 최종 판단 | 근거/보완 내용 |
| --- | --- | --- |
| 서로 다른 자동화 도구 2개<br>이상 | 충족 | Make와 Zapier를 실제 사용 |
| 동일한 워크플로우 구조 | 충족 | Google Sheets 새 행 감지 → 처리이력 기록 → 80점 기준 분기 →<br>Gmail 통보 |
| Trigger 1개 이상 | 충족 | 양 도구 모두 Google Sheets의 신규 응답 행을 시작점으로 사용 |
| Action 2개 이상 | 충족 | ① 처리이력 시트 행 추가 ② Gmail 이메일 발송 |
| 조건 분기 1개 이상 | 충족 | Make Router+Filter / Zapier Paths 조건 분기 |
| 분기 경로별 1회 이상 실행 | 충족 | 83점 합격과 71점 재응시 사례가 실제 발송되었고 Zapier는 양쪽<br>Path 실행 화면이 확인된다. Make도 동일 입력에 반응한 실행<br>기록이 있음 |
| 비교 항목 5개 이상 | 충족 | 본 보고서에서 10개 항목 비교 |
| 도구별 장단점 | 충족 | 7장에 정리 |
| 적합 상황 의견 | 충족 | 8장에 정리 |
| 민감정보 마스킹 | 충족 | 최종보고서 삽입 화면은 계정 식별부를 블러 처리 |
| 유료 기능 사용 사유/무료 대안 | 충족 | Make는 Free 범위의 Router/Filter를 활용. Zapier는 Paths를<br>포함한 다단계 구성을 위해 신규 계정의 Professional 14일<br>무료체험을 활용했으며, 무료 대안은 동일 과제에서 사용한<br>Make의 Router/Filter 구성임 |

## 2. 자동화 업무 정의

- 자동화 업무: Google Form으로 입력된 평가 결과가 Google Sheets에 저장되면 해당
응답을 별도의 처리이력 시트에 기록하고, 점수가 80점 이상인지 여부에 따라 합격
또는 재응시 안내 이메일을 자동 발송한다.
- 입력 데이터: Google Form 응답이 연결된 Google Sheets 행
- 판정 기준: 점수 80점 이상 = 합격 / 80점 미만 = 재응시
- 기록: 동일 응답을 「처리이력」 시트에 추가
- 통보: Gmail을 이용하여 결과 이메일 자동 발송
- 비교 도구: Make, Zapier

| 단계 | 역할 | 처리 내용 |
| --- | --- | --- |
| 1 | Trigger | Google Sheets에서 신규 응답 행 감지 |
| 2 | Action 1 | 처리이력 시트에 응답 정보 추가 |
| 3 | 조건 분기 | 점수 ≥ 80 / 점수 < 80 |
| 4-A | Action 2 | 합격 안내 이메일 발송 |
| 4-B | Action 2 | 재응시 안내 이메일 발송 |

### 4.2 실행 및 로그 확인

- Zap runs에서 개별 실행 건의 성공/실패 여부를 확인한다.
- Zapier의 task는 성공적으로 실행된 Action을 기준으로 계산되며 Trigger와
Filter/Paths는 task로 계산되지 않는다. 따라서 폴링 자체가 task로 계산되지 않는
점은 Make의 credits 관리 방식과 비교할 때 사용량 관리 측면의 차이로 볼 수 있다.

## 6. Make vs Zapier 비교 분석

| 비교 항목 | Make | Zapier | 본 과제 관점 평가 |
| --- | --- | --- | --- |
| 1. UI/UX | 캔버스 위 모듈 연결의 시각적 노드<br>방식. 전체 분기 구조를 한눈에 보기<br>쉬움. | 단계별 카드/리스트 중심. 초보자가<br>순서대로 설정하기 쉬움. | 복잡한 분기를 설명하는 발표·보고서에는<br>Make가 직관적. |
| 2. 초기 설정 난이도 | Mapping, bundle, router/filter<br>개념을 익혀야 해 초기 학습량이<br>있음. | Trigger와 Action을 순서대로 안내해<br>초반 진입이 쉬운 편. | 초보자 시작은 Zapier, 구조 이해·확장은<br>Make가 유리. |
| 3. 조건 분기 | Router & Filters가 Free에 포함. | Paths는 Free에서 사용할 수 없고<br>다단계 구성은 Professional 이상<br>또는 무료체험이 필요. | 무료 수행이 중요하면 Make가 우세. |
| 4. 연동 앱 범위 | 공식 페이지 기준 3,000+ 앱. | 공식 페이지 기준 9,000+ 앱. | 서비스 수는 Zapier가 더 넓지만 본<br>과제의 Google Sheets/Gmail은 둘 다<br>지원. |
| 5. 무료 플랜 | 1,000 credits/월, Router/Filter 포함,<br>최소 15분 실행 간격. | 100 tasks/월, Free는 one trigger +<br>one action의 2-step Zap. | 이번 다단계 분기 워크플로우는 Make<br>Free가 현실적으로 유리. |
| 6. 사용량 계산 | 모듈 실행이 credits에 영향을 주며<br>스케줄 운영 방식에 따라 credits<br>관리가 중요. | 성공한 Action이 task로 계산되고<br>Trigger·Filter·Paths는 task 미계산. | Make는 credits/스케줄 관리, Zapier는<br>Action 수 관리가 핵심. |
| 7. 실행 로그 | History와 각 모듈의 bundle<br>input/output를 상세히 확인 가능. | Zap runs에서 실행 상태와 단계별<br>상태를 확인. Filtered 등 상태 표현이<br>명확. | 데이터 흐름 디버깅은 Make가 세밀하고<br>실행 상태 파악은 Zapier가 간결. |
| 8. 분기 시각화 | Router에서 여러 갈래를 한 화면에<br>표현하기 좋음. | Paths로 분기하지만 카드가 세로로<br>길어질 수 있음. | 과제의 조건 분기 설명에는 Make 화면이<br>더 설명하기 쉬움. |
| 9. 중복/테스트 관리 | Run once와 시작 지점 설정 등<br>테스트 제어가 강력하나<br>활성화·스케줄 관리에 주의 필요. | 개별 Zap run 기록이 명확하지만 Pro<br>기능/Task 한도를 함께 관리해야 함. | 두 도구 동시 테스트 시 별도 시간대 또는<br>Tool 열을 두는 것이 좋음. |
| 10. 추천 상황 | 복잡한 분기, 다단계 데이터 변환,<br>비용 민감 실습, 시각적 설계가<br>중요한 경우. | 많은 앱 연동, 간단한 업무를 빠르게<br>구성, 안내형 UI를 선호하고 유료<br>플랜 사용이 가능한 경우. | 이번 동일 분기 비교에서는 Make를 기준<br>구현, Zapier를 비교 구현으로 두는<br>구성이 설득력 있음. |

## 7. 도구별 장단점 정리

### 7.1 Make

| 구분 | 내용 |
| --- | --- |
| 장점 | ① Router/Filter가 무료 플랜에 포함되어 과제 요구 충족이 쉽다. ② 전체 흐름이 시각적으로 보여<br>분기 구조 설명이 쉽다. ③ bundle 단위 input/output 확인이 상세하다. ④ 복잡한 다단계 자동화<br>확장성이 좋다. |
| 단점 | ① 초보자에게 Mapping, bundle, credits 개념이 어렵다. ② 폴링형 Trigger를 스케줄로 운영하면<br>정기 실행에 따른 credits 관리가 필요하다. ③ 여러 분기와 모듈이 늘어나면 화면이 복잡해질 수<br>있다. |

### 7.2 Zapier

| 구분 | 내용 |
| --- | --- |
| 장점 | ① 단계별 설정 방식이 명확해 초보자가 따라가기 쉽다. ② 연동 앱 생태계가 매우 넓다. ③ Zap<br>runs에서 성공/Filtered/Errored 등 상태를 파악하기 쉽다. |
| 단점 | ① Free는 2-step Zap으로 제한되어 본 과제와 같은 다단계 분기 구현에 적합하지 않다. ② Paths와<br>다단계 워크플로우는 Professional 이상 또는 무료체험이 필요하다. |

## 8. 어떤 상황에 어떤 도구가 적합한가

- Make가 더 적합: 무료 범위에서 Router/Filter를 써야 하는 교육 실습, 여러 조건
분기, 데이터 변환 단계가 많은 업무, 실행 데이터의 세밀한 디버깅이 필요한 경우.
- Zapier가 더 적합: 연결하려는 서비스 종류가 매우 많고, 간단한 자동화를 빠르게
만들고 싶으며, Professional 이상 플랜 또는 무료체험을 사용할 수 있는 경우.
- 이번 과제의 판단: 같은 평가 자동화를 두 도구로 비교하는 목적에는 두 제품 모두
적절하지만, “무료 플랜 우선” 조건까지 고려하면 Make 쪽이 과제 요구와 더 잘
맞는다.

## 9. 보안 및 제출물 처리

- API Key, OAuth token, 비밀번호는 어떤 화면에도 노출하지 않는다.
- Gmail/Google 계정 이메일은 전체 주소를 그대로 보여 주지 않고 일부 마스킹 또는
블러 처리한다.
- 본 최종보고서에 삽입한 화면은 계정 식별 영역을 블러 처리한 버전을 사용했다.
- Google Sheets 응답자 이메일은 제출 목적상 전체 주소가 필요하지 않으므로 ***
또는 부분 마스킹으로 처리한다.
- 공유 링크를 제출할 경우 “링크가 있는 모든 사용자 편집 가능” 같은 과도한 권한을
피하고 최소 권한 원칙을 적용한다.

## 10. 최종 결론

기존 구현은 Google Sheets 신규 응답을 Trigger로 하여 처리이력 기록, 80점 기준 조건
분기, Gmail 결과 통보를 Make와 Zapier에서 각각 실행한 것으로 확인된다. 따라서 Project
1의 핵심인 “두 도구를 직접 사용한 동일 워크플로우 비교 구현”은 성립한다. 다만 평가
증빙의 명확성을 높이기 위해서는 Make에서도 합격/재응시 각 분기의 상세 Run 로그를
별도로 확보해 두는 것이 가장 확실하다.

## 1. 과제 개요 및 최종 판단

### 1.1 과제 목표

Project 2는 반복 업무 1개를 정의하고 자동화 도구 1개를 선택한 뒤, 실제로 자동 실행되는
워크플로우를 구현하여 설계 흐름·구현 화면·실행 결과를 증빙하는 과제이다. 공통
요구사항으로 Trigger 1개 이상, Action 2개 이상, 조건 분기(Filter/Router) 1개 이상이
필요하며, 분기 구조를 사용했다면 각 분기 경로가 실제로 최소 1회 이상 실행되었음을
확인해야 한다. Bonus 1은 생성형 AI Action, Bonus 2는 실패 알림과 재시도 또는 대체 경로
설계이다.

## 2. 자동화할 반복 업무 정의

자동화 대상은 「AI 기초교육 평가 결과 자동 판정 및 안내」 업무이다. 사람이 매번 Google
Form 응답을 확인하고 점수를 판정하여 개별 메일을 작성하는 반복 업무를 자동화한다.

| 구분 | 설계 내용 |
| --- | --- |
| 입력 | Google Form 응답이 연결된 Google Sheets 신규 행: 접수시각, 이름, 이메일, 점수 |
| 입력 검증 | 필수값 누락 여부와 정상 점수 범위를 확인. 부적합하면 합격/재응시 판정을 중단 |
| 판정 기준 | 점수 80점 이상 = 합격 / 80점 미만 = 재응시 |
| AI 처리 | 합격·재응시 유형별로 AI가 개인화 안내문을 생성 |
| 기록 | 합격자/재응시자 시트에 처리 결과와 AI 안내문 기록 |
| 통보 | Gmail로 해당 응시자에게 결과 안내 자동 발송 |
| 부적합 입력 | 실패로그에 기록하고 관리자에게 확인 필요 메일 발송. 응시자 결과 메일은 보내지<br>않음 |
| AI/후속 오류 | 오류 처리 경로에서 에러 발생 시트 기록 → 관리자 Gmail → Resume로 흐름<br>종료/계속 처리 |

### 2.1 자동화 전·후 비교

| 구분 | 내용 |
| --- | --- |
| 수작업 | 응답 확인 → 점수 판정 → 메일 문안 작성 → 대상자 메일 발송 → 결과 기록 →<br>오류 확인을 사람이 반복 |
| 자동화 후 | 신규 응답 감지부터 판정·AI 문안 작성·시트 기록·메일 발송·오류 관리자 통보까지<br>시나리오가 자동 수행 |
| 업무 효과 | 판정 누락과 메일 작성 반복을 줄이고, 정상/비정상 입력을 분리하여 잘못된 결과<br>메일 발송 위험을 줄임 |

## 3. 자동화 도구 선정 및 선정 이유

### 3.1 선정 도구: Make

Project 1에서 Make와 Zapier를 비교한 경험을 바탕으로 Project 2는 Make를 선택하였다.
현재 Make 공식 가격표에서도 Free 플랜에 1,000 credits/month, Routers & filters, 15-minute

minimum interval이 포함되는 것으로 안내되어 있어, 다중 분기 구조를 교육 과제로
구현하기에 적합하다(2026.8.16. 확인).

| 선정 근거 | 설명 |
| --- | --- |
| 조건 분기 | Router/Filter를 시각적으로 한 화면에 배치할 수 있어 입력 검증·합격·재응시·오류<br>경로를 설명하기 쉬움 |
| 무료 실습 범위 | 현재 Free 플랜에 Router & filters와 1,000 credits/month가 포함되어 과제 실습에<br>유리 |
| AI 확장 | Make AI Toolkit/AI Provider를 이용한 AI Action을 동일 시나리오에 연결 가능 |
| 오류 처리 | Error Handler, Resume, Retry 등 오류 처리 기능이 있어 Bonus 2 확장에 적합 |
| 증빙성 | 시나리오 캔버스 자체가 설계도 역할을 하며 History에서 실행 상태를 확인할 수<br>있음 |

### 3.2 선정 시 유의점

- Google Sheets의 Watch New Rows는 폴링형 Trigger이므로 스케줄을 계속 켜 두면
정기 실행에 따른 credits가 발생할 수 있다. 실습 종료 후 불필요한 Scenario는
비활성화하는 것이 안전하다.
- 복잡한 분기에서는 모듈 수가 빠르게 늘어나므로 “입력 검증 → 정상 판정 → 결과
처리 → 오류 처리”처럼 단계별 이름을 명확히 붙이는 것이 중요하다.
- AI 생성 문안은 편리하지만, AI 실패 시에도 잘못된 응시자 메일이 발송되지 않도록
대체 경로와 관리자 확인 절차가 필요하다.

## 7. Bonus 1 - AI 연동 Action

### 7.1 구현 내용

합격 경로에는 「AI_합격안내문_생성」, 재응시 경로에는 「AI_재응시안내문_생성」 Simple
Text Prompt 모듈이 배치되어 있다. AI 출력은 각각 합격자/재응시자 시트의 “AI 생성
안내문” 필드에 저장되고 Gmail 본문으로 사용된다.

| 경로 | AI 입력 | AI 출력 역할 | 후속 사용 |
| --- | --- | --- | --- |
| 합격 | 점수·이름 등 입력 정보 | 축하 문구 + 합격 기준 충족 안내 + 향후<br>학습 격려 | 합격자 시트 및 Gmail |
| 재응시 | 점수·이름 등 입력 정보 | 현재 점수 안내 + 재응시 필요 안내 + 격려<br>문구 | 재응시자 시트 및 Gmail |

### 7.2 AI 사용의 실제 가치

- 동일한 판정 결과라도 사용자별 안내 문장을 다르게 생성하여 고정 템플릿보다
