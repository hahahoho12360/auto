# 운영 상태와 범위

이 시스템은 GitHub의 일일 자료 수집과 별도 ChatGPT/Gmail 보고 예약으로 구성한다. 대상 193기관은 실제 연결 성공 수가 아니다. 전체 연동 검증은 아직 미완료이다.

## 실제 확인

- 첫 수집 실행 39206309763: 정상 종료, 목록 확인 11 / 부분 확인 15 / 미확인·실패 167.
- 두 번째 실행 39207814433: 정상 종료, 목록 확인 0 / 부분 확인 16 / 미확인·실패 177. 느린 사이트가 본문·첨부 처리 시간을 독점하여 실행시간 상한에 도달했다.
- 최신 코드는 이 문제를 해결하기 위해 모든 기관의 목록을 먼저 확인하고, 본문·첨부 확인을 뒤로 분리했다. 목록 단계 최대 420초, 상세 단계 추가 100초이며 네트워크 정리시간이 더 걸릴 수 있다. 전체 작업 한도는 23분이다.
- 교육부·시도교육청을 먼저 배치하고, 교육지원청은 지역별 순환 순서로 처리한다. 같은 호스트의 연속 전송 실패 2회 후에는 해당 실행의 추가 접속을 중단한다. 404는 호스트 전체 장애로 처리하지 않는다.
- 테스트는 34개다. 테스트 통과는 실제 전국 연동 완료를 뜻하지 않는다.
- 실제 최신 결과는 education-audit-data 브랜치 latest.json/latest.md/heartbeat.json을 확인한다.

## 최신 범위

매일 변경 점검만 수행하며 월간 작업은 없다. 등록된 공개 경로의 최근 최대 3개 목록 페이지를 확인한다. 본문·첨부 상세 확인은 전체 실행에서 최대 32개 게시글을 기관별로 나누어 시도한다. 신규·미확인 자료를 우선하되, 상세 처리시간을 초과하면 남은 자료는 미확인으로 보고한다. 이 규칙은 기존 README/config의 게시판별 상세 최대12개보다 우선한다. 12개 값은 구형 일반 엔진의 설정이며 현재 실행기는 목록 단계에0을 전달한다.

`institutions_with_any_listing_checked`는 등록 경로 중1개 이상 목록을 확인한 기관 수, `institutions_with_all_registered_listings_checked`는 등록 경로 모두의 목록을 확인한 기관 수다. 이는 전국 모든 감사 공개 경로를 찾았거나 첨부 전체를 읽었다는 의미가 아니다. `detail_checks_succeeded`는 상세 응답 처리 수이며 첨부 내용 확인 상태와 구별한다.

수집기가 메일을 보내지는 않는다. 별도07:40보고 예약이 실제 연결 Gmail을 이용한다. 비밀번호·수신자 주소를 공개 코드에 넣지 않는다. 발송 성공과 수신함 도착은 구별한다. 기존08:00기사 브리핑은 수정하지 않는다.

공개 저장소의 표준Linux runner와 유료API미사용을 전제로 추가 직접 비용0원을 목표로 한다. 비공개 저장소로 전환되면 수집작업을 실행하지 않는다. 기존구독비와 계정의 다른 사용료는 별개이며, 계정 결제한도를 바꾼 것은 아니다.
