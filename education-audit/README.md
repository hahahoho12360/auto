# 전국 공개 교육감사 변경 모니터

## 구성
교육부 1, 시·도교육청 16, 교육지원청 176을 대상 명부로 등록한다. **명부 등록은 홈페이지/게시판 확인 또는 193기관 수집 성공을 뜻하지 않는다.** 공식 상위기관 홈페이지에 게시된 링크로 미확정 기관 주소를 탐색하고, 실제 확인률은 매일 보고한다.

- 수집: `.github/workflows/education-audit.yml`, 매일 06:35 Asia/Seoul (UTC 전일 21:35).
- 메일: 별도 ChatGPT 예약이 매일 07:40 Asia/Seoul 시작. 연결 Gmail 사용. 비밀번호/메일주소는 이 공개 저장소에 저장하지 않는다.
- 코드: `education-audit/monitor.py`, 설정: `config.json`.
- 데이터: `education-audit-data` 브랜치의 `latest.json`, `latest.md`, `heartbeat.json`, `report-index.json`, `registry.json`, `state.json`.
- 월간 정밀점검 및 유료 API 호출: 없음.
- 본 저장소의 기존 과제 파일/README는 수정하지 않는다.

## 실행/시험
```sh
python -m pip install -r education-audit/requirements.txt
python -m unittest discover -s education-audit -p 'test_*.py' -v
python education-audit/monitor.py --out audit-data
```
실서비스 상태는 데이터 브랜치를 체크아웃한 폴더로 지정해야 실행 간 보존된다. 로컬 `audit-data` 폴더는 발송 시스템과 자동 연결되지 않는다.

## 보고서
매일 신규·수정·확인 실패를 분리한다. 최초 관측은 기존 자료 baseline이며 신규 발생으로 일괄 발송하지 않는다. 첫 관측일 기준 최근 14일 자료는 별도 참고란에 표시한다. 동일 날짜 재실행은 발견 이벤트를 합쳐 앞선 발견이 사라지지 않게 한다. 최근 31일 일별 보고서를 보관하고, 발송 누락은 별도 Gmail 보낸편지함 기록과 대조한다. state는 당일 발송 여부가 아닌 관측 이력이다.

## 수집 범위와 한계
기본 점검 범위는 등록 감사 공개 경로의 최근 최대 3개 목록 페이지이다. 게시판별 하루 최대 12개 본문을 신규·미확인/오래된 확인순으로 점검한다. 게시글별 6개 첨부, 12MiB/파일, PDF 200쪽, 텍스트 40만자, 변환 25초 상한이다. 상한에 걸리거나 파서를 확정하지 못한 자료는 미확인으로 보고한다. 암호/스캔문서, 복합 ZIP 묶음, 로그인/차단된 자료를 읽었다고 요약하지 않는다. 모든 과거 첨부 교체를 매일 전수 검사하는 시스템은 아니다. 공개되지 않은 감사는 수집할 수 없다.

## 요약
수집기는 문서 내용 중 감사 관련 문장을 규칙으로 발췌한다. 유료 AI는 호출하지 않는다. 별도 예약 보고 단계가 확인된 발췌와 원문 링크를 한국어로 정리한다. 첨부 미확인을 확인 완료로 바꾸지 않는다. 해석·경남 적용 제안은 원문 사실과 분리한다.

## 비용 및 보안
공개 저장소 표준 `ubuntu-latest` runner만 실행한다. 유료 외부 API, Actions cache/artifact를 사용하지 않는다. 비공개 전환 시 job을 실행하지 않는다. 기존 ChatGPT 구독을 제외한 추가 직접 비용 0원을 목표로 하며, GitHub 요금정책 변경/계정의 다른 작업 비용까지 이 코드가 통제하지는 않는다. 사용자의 결제 설정을 변경하지 않는다.

robots를 준수하고 공개 도메인/IP만 허용하며 SSL 검증을 끄지 않는다. 로그인·암호화·접근제한을 우회하지 않는다. 문서 안의 명령을 실행하거나 이메일 수신자를 바꾸지 않는다. 원본 바이너리를 공개 저장소에 재게시하지 않는다. 발췌문에서 이메일·전화·주민등록번호 형태를 가린다. 개인정보 완전 제거를 보증하지 않으므로 공개본만 입력한다.

## 유지관리
신규 홈페이지/게시판은 공식 출처 확인 후 config에 반영한다. `homepage_unresolved`, `audit_board_unresolved`, `list_parser_unverified`, `some_content_unread`를 점검한다. 마지막 실행 heartbeat와 최신 보고서 날짜를 확인한다. 07:40 예약은 최신 보고서가 없을 때 장애 보고를 발송하며, 수집 성공으로 가장하지 않는다.

GitHub 예약 실행과 AI 보고서 작성은 지연될 수 있어 07:40은 보고 작업 시작시각이며 메일 도착시각의 초단위 보장은 아니다. 수신 확인은 별도 실제 받은편지함에서 검증한다.
